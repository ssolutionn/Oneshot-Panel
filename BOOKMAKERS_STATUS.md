## Что означает статус

- «—» — источник успешно прочитан, матч в полученной части линии не найден.
- «?» — источник ещё проверяется, недоступен, ответ неполный или парсер не подключён.
- «Данные устарели» — показан последний успешный ответ этого окна; свежие коэффициенты не подтверждены.
- «Только прематч» — данный адаптер не проверяет текущие лайв-матчи.
- Одиннадцать адаптеров не означают постоянную доступность всех одиннадцати. Ошибка отдельного источника сохраняет старый результат с отметкой времени.

## Ограничения и безопасность

API только GET, только фиксированные источники. Параметр id не превращается
в URL; редиректы не выполняются. Общий бюджет зеркал 24 секунды, один
источник не задерживает таблицу остальных. Ответы HTTP ограничены 16 МиБ,
WebSocket — размером пакета, суммарным потоком и временем подключения.
Короткий кэш в памяти хранит только завершённые ответы. Незавершённые запросы
не разделяются между посетителями: Cloudflare привязывает сетевой ввод-вывод
к исходному запросу, закрытие одной страницы не должно блокировать остальные.

Нет входа в аккаунты букмекеров, чужих cookies, паролей, ключей, обхода капч
или подделки подписанных заголовков. На сайте не появился серверный ввод
на запись. Названия выводятся текстом, ссылки ограничены доменами контор,
CSV защищён от формул из внешних строк. Локальные наблюдения недели сохраняются в браузере; общий архив дней —
в отдельной ветке GitHub `bookmaker-history` (только публичные сведения о матчах).
Сайт читает его через `/api/bookmakers?history=YYYY-MM-DD`; серверного ввода на запись нет.

Для Winline HTTP Upgrade реализован под Cloudflare. В средах без
серверного WebSocket Upgrade этот источник вернёт недоступность; остальные
адаптеры используют обычный HTTP. npm-зависимости не добавлены.

## История по игровым дням

«Какие матчи были в линии» показывает все 16 контор, день выбирается по МСК.
Это зафиксированные предложения, а не подтверждение результата матча или того,
что линия существовала весь день. Запись не исчезает после пустого ответа или
ошибки БК. Хранятся команды, время матча, исходное название турнира, первые
замеченные и последние коэффициенты, первое/последнее наблюдение, появление в лайве.
CSV дня включает общий архив и локальные наблюдения; прежний CSV недели сохранён.

Workflow `bookmaker-history.yml` читает опубликованный API Cloudflare примерно
раз в 10 минут и атомарно сохраняет `days/YYYY-MM-DD.json` в ветке
`bookmaker-history`. Временные задержки GitHub Actions возможны, короткая линия
между проверками может быть пропущена. Планировщик работает при закрытом сайте.
Срок удаления архивных дней не задан; файлы сохраняются отдельно от исходников.
Секрет записи GitHub доступен только job сохранения, не сайту и не Cloudflare.
Новые сервисы, npm-зависимости, API записи, сторонние cookies не нужны.
При недоступности общего архива показываются локальные наблюдения с предупреждением.
Автоматическое отключение scheduled workflows GitHub после 60 дней без активности
репозитория нужно учитывать для межсезонья.

пустыми CyberClash-списками. Это отсутствие предложений в полученных лентах,

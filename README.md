# Oneshot Panel

Веб-панель CyberClash: составы из Google Sheets, ссылки VDO.Ninja,
коллекции сцен OBS 1920×1080 и вето в формате HLTV.
Внешних npm-зависимостей нет. Нужен Node.js >=22.

## Запуск

```sh
npm run check
npm test
npm run dev
```

По умолчанию порт 3000. Другой порт: `PORT=3001 node server.js`.
Для доступного извне сервера: `HOST=0.0.0.0`.
Для статического размещения нужны index.html, app.js, core.js, theme.js,
style.css, card.html, card.js, card.css, live.js, obs.js, vdo.js, lobby.js,
faceit.js, obs-bridge.html, obs-bridge.js, veto.html, veto.js, veto.css,
veto-room.js и assets/, с сохранением путей
от корня сайта. На Netlify ещё работает `netlify/functions/faceit.mjs`
(прокси FACEIT на `/api/faceit`).

Размещение на своём сервере (nginx) или домене — `DEPLOY.md`.

Netlify: подключите репозиторий, остальное задаёт `netlify.toml`.
Cloudflare Pages (бесплатно, 500 сборок в месяц) — `DEPLOY.md`,
«Вариант 3»: build command `sh scripts/build-site.sh`, папка `public`.
Компиляции нет: `scripts/build-site.sh` копирует в `public/` те же файлы,
что отдаёт `server.js`, и публикует только их, с теми же заголовками
безопасности (тесты следят, чтобы список и заголовки не разошлись).
Ещё она пишет в `build.txt` коммит сборки: GitHub Actions ждёт, пока
на сайте появится именно этот коммит, и только потом проверяет сайт.

1. app.netlify.com → Add new site → Import an existing project → GitHub.
2. Репозиторий `ssolutionn/Oneshot-Panel`, ветка `claude/gracious-sagan-apztcc`.
   Build command и Publish directory Netlify возьмёт из `netlify.toml`.
3. Deploy. Затем Site configuration → Change site name, например
   `oneshot-panel` → https://oneshot-panel.netlify.app.
4. Каждый push в ветку выкладывается сам.

Таблица составов должна быть открыта по ссылке только на просмотр:
ссылка на неё видна в панели всем, кто её открыл.

## Использование

- Выберите матч из расписания или команды вручную.
- Время московское; время и стадия нужны для имени JSON.
- В слотах можно выбирать основных, запасных и тренеров.
- Обновление составов сохраняет выбранные замены,
  пока эти игроки присутствуют в таблице.
- Для игроков копируется заголовок команды и строки:
  `**Ник** https://vdo.ninja/...`.
- Ссылка утекла? Справа от игрока кнопка **↻**: нажми два раза — у
  игрока новый ID потока, сообщение с новой ссылкой сразу в буфере,
  отправь его игроку. Старая ссылка больше не его камера. Камеру в OBS
  обновит «Отправить в OBS» (кнопка подсвечивается) или новый JSON.
  Новый ID хранится в этом браузере, пока в таблице (колонка E) прежний;
  впиши его туда, чтобы видели все. «вернуть» в строке отменяет.
- Для обсервера копируется только порядок слотов 1–10
  (`1. Команда — Ник`), без ссылок: камеры приходят в JSON для OBS.
- Экспорт: `16-00_Группа-B_Команда-A_vs_Команда-B.json` — без пробелов:
  части через `_`, пробелы внутри названий заменяются на `-`.
- Импорт: OBS → Коллекция сцен → Импорт.
- Вето поддерживает BO1/BO2/BO3/BO5, первый ход, выбор CT/T
  для соперника на пике, отмену, сброс и копирование текста HLTV.
- Подготовка матча и завершённые ходы сохраняются в браузере.
- Смена пары команд или выбранного матча сбрасывает вето.
- Расписание берётся из таблицы организатора, лист
  «Schedule (Group Stage)»: в списке матчи на сегодня и следующие дни,
  сгруппированные по датам («15.10 · сегодня», «16.10 · завтра»).
  Прошедшие дни исчезают сами, матчи без команд (Losers, Winners)
  появятся, когда организатор впишет команды. Ничего вручную
  переносить не нужно.
- Дневной лист «Матчи ДД.ММ» тоже понимается: укажите его GID
  в «Источник данных». Если он составлен на другой день (по заголовку
  «Матчи 14 октября 2026»), панель предупреждает.
- Плей-офф (с 29.10): в веб-версии укажите в «Источник данных» GID
  листа «Schedule (Playoffs)»; артефакт Claude читает оба листа сам.
- Если картинок карт нет, панель показывает текст и цвет
  без значков битых изображений.
- Дневной и ночной режим: кнопка «☾ Ночь / ☀ День» в шапке.
  Днём шапка светлая с чёрным логотипом, ночью тёмная с белым.
  Без выбора панель следует теме системы; выбор запоминается
  в браузере (`theme.js` грузится в `<head>`, без вспышки).

## Логотипы команд

Логотип показывается в карточке команды на тёмной плашке (в обоих
режимах: часть логотипов белая). Если логотипа нет — значок A/B.

- Файлы: `assets/teams/<имя>.png`, список: `assets/teams/teams.json`
  (`"Название команды как в таблице": "файл.png"`). Одной картинке
  можно дать несколько названий, например `"Aces"` и `"Black Phoenix"`.
- Добавить вручную: загрузите PNG в `assets/teams/` на GitHub и
  допишите строку в `teams.json`. Или пришлите картинку Claude.
- Из таблицы организатора: логотипы лежат картинками на листе
  «Teams (Group Stage)» рядом с названиями. Скачайте таблицу как .xlsx
  и запустите `python3 scripts/extract_team_logos.py файл.xlsx`
  (нужен Pillow): скрипт сохранит картинки (до 128 px) и допишет
  `teams.json`, ручные строки сохраняются.
- Сейчас все 16: 13 из таблицы организатора, PRIVATE, 6yuBoJlbl
  и Lavked прислали отдельно (в таблице организатора их нет).
- Артефакт Claude встраивает логотипы в страницу при сборке.
- Карточка игрока берёт логотипы отсюда же.

## Вкладки

- «Подготовка» — всё для матча: расписание, составы и вебки, OBS, вето,
  тексты обсерверу и игрокам.
- «Лобби» — турнир FACEIT во время игрового дня (ниже).
- Выбранная вкладка запоминается; `/#lobby` открывает лобби сразу.

## Статус вебок

Галочка «Следить за вебками» (включена по умолчанию) подключает к
комнатам команд скрытого зрителя VDO.Ninja без звука и видео. На номере
слота точка: зелёная — игрок публикует камеру, красная — камеры нет,
жёлтая — проверяем. У команды счётчик «4/5», сверху итог
«Все вебки на месте · 10/10» или «Нет камеры: 2 · 8/10 в эфире».
Игрокам это ничего не стоит: зритель не просит ни видео, ни звук.

## Отправить в OBS

Кнопка «Отправить в OBS» переводит уже открытую в OBS коллекцию на
выбранный матч: камеры CAM 01–10 получают новые ссылки и имена, карточки
CARD (если включены) создаются прямо под камерами или скрываются.
Коллекцию из JSON импортируют один раз, дальше — кнопка. «Скачать JSON»
и «Копировать JSON» остаются запасным путём.

Настройка — отдельная вкладка **«OBS»** в верхнем меню (точка рядом —
статус: зелёная — на связи). Сверху форма «Подключение к OBS»: выбор
компьютера, поля подключения, «Проверить связь». Под ней пошаговая
инструкция с нуля: загрузить коллекцию сцен, включить WebSocket, подключить
панель (на этом компьютере или у обсервера), что жать каждый матч, графика
вето и «что-то не так — что делать». Кнопка «OBS не настроен» рядом с
экспортом тоже открывает вкладку, «← К подготовке» возвращает.

- **OBS на другом компьютере** (обсервер в той же сети или в другом
  городе): обсервер один раз добавляет док — OBS → Док-панели →
  Пользовательские док-панели браузера, имя «Oneshot», адрес — ссылка
  из блока «Подключение к OBS» (`/obs-bridge.html#k=<код>`). В доке вписывает
  пароль OBS WebSocket (Сервис / Tools → Настройки сервера WebSocket →
  «Включить», «Показать сведения о подключении»). Связь идёт через
  VDO.Ninja: без проброса портов и туннелей; команды зашифрованы кодом
  связи. «Сменить код» отключает старый док.
- **OBS на этом компьютере**: в полях блока укажи адрес
  `ws://127.0.0.1:4455` и пароль из «Показать сведения о подключении».
  Если в OBS другой порт, замени `4455`. «Сохранить подключение» сохраняет
  настройки на этом компьютере; «Проверить связь» проверяет их без отправки матча.
- «Проверить связь» показывает, отвечает ли OBS. Статус у кнопки:
  «Док OBS на связи», «Док на связи, OBS не подключён», «Док OBS не на связи».

### OBS у обсервера (другой компьютер, другая сеть)

Сайт не может сам зайти в чужой OBS. Поэтому обсервер один раз добавляет в
свой OBS **окно Oneshot** (в OBS это «док»): оно получает команды сайта через
интернет (VDO.Ninja, зашифровано кодом связи) и передаёт их OBS на том же
компьютере. IP, порты и одна сеть не нужны.

1. «Подключение к OBS» → «У обсервера» → **Скопировать сообщение** и отправь
   обсерверу (на телефоне — «Поделиться»). В сообщении ссылка и три пункта:
   Док-панели → Пользовательские док-панели браузера → имя Oneshot, адрес из
   сообщения → вписать пароль WebSocket в окне Oneshot → «Подключить».
2. Статус в шаге 2 станет зелёным: «Всё подключено ✓».

Если обсервер не может вписать пароль — «Впиши за него»: порт и пароль из
OBS («Показать сведения о подключении») вручную или QR/скриншотом; док
сохранит их, только если OBS их принял. В «Другие способы»: подключиться к
уже добавленному окну Oneshot по его коду или QR («Подключить телефон по QR»
в самом окне), ссылка без текста, смена кода. У каждого браузера свой код.

QR Oneshot содержит только код связи, без пароля OBS; он даёт управление
эфиром — передавай только своей команде. Ссылку на оверлей вето копируй с
того устройства, на котором проводишь вето.

## Оверлей вето

Анимированный оверлей Codex: `assets/veto-overlay/overlay.html` (весь
экран или плашка снизу, дым, анимации банов и пиков).

1. На сайте нажми **«Ссылка на оверлей для OBS»**. Живое обновление включится автоматически.
2. В нужной сцене OBS: **Источники → + → Браузер**, имя «Вето».
3. Вставь скопированный адрес в URL. Для «Весь экран» размеры **1920 × 1080**,
   для «Плашка снизу» — **1920 × 400**, нажми ОК. Нижнюю плашку в сцене
   1920×1080 поставь в **X = 0, Y = 680**; камера отдельным источником ниже
   плашки в списке остаётся видна в верхней части кадра.
4. Дождись на сайте статуса **«Оверлей получает вето»**, затем кликай баны и пики.
   Дым движется постоянно, карты анимируются при новом ходе.

Док Oneshot — панель управления камерами; графика добавляется отдельным
источником. Для самого живого вето WebSocket и пароль OBS не нужны:
сайт публикует состояние через отдельный зашифрованный поток данных VDO.Ninja,
а источник в OBS подтверждает его получение. Код этой связи находится в
фрагменте ссылки `#s=…&r=…`; это отдельный код показа графики, он не даёт
управлять OBS и не содержит пароль WebSocket.

Ссылка сохраняет снимок на момент копирования, а живые ходы приходят поверх
него. Панель повторяет текущее состояние каждые 2,5 секунды: после загрузки
или обновления источника оно восстановится без нового клика. Пока сайт
закрыт или живое обновление выключено, источник сохраняет последний кадр.
Если статус «Ждём оверлей» не исчезает, проверь URL браузерного источника:
после обновления со старой версии скопируй новую ссылку с `&r=` и замени URL.
Оба компьютера должны иметь доступ к VDO.Ninja.

- На телефоне открой панель в Safari/Chrome. Вето веди именно здесь;
  ссылку оверлея скопируй с телефона и передай на ПК с OBS. У каждого
  браузера свой код связи: старая ссылка из панели ПК не относится к телефону.
- Для управления камерами с телефона: вкладка «OBS» → «У обсервера» →
  «Сохранить подключение»; ссылку дока с телефона вставь в док OBS на ПК.
  Адрес 127.0.0.1 и пароль OBS вводятся в доке на компьютере.
- Выбор «Весь экран» / «Плашка снизу» задаёт вид копируемой ссылки.
  Новые ссылки нижней плашки содержат crop=1 и дают настоящий источник
  1920×400. Старые ссылки без crop=1 сохраняют прозрачный верх 1080p.
- Карты в самой панели идут по ходу вето: выбранные баны/пики первыми,
  затем оставшийся пул. Номер хода и команда видны на карточке.
- PICK виден сразу после выбора карты; стартовую сторону выбирает соперник.
  Подтверждение стороны не запускает PICK повторно.
- После последнего хода десайдер раскрывается через 1,5 с. Повторы состояния
  не продлевают задержку; загрузка готового вето показывает итог сразу.
- Демо без матча: `/assets/veto-overlay/overlay.html?preview=1`.
- При недоступном WebGL дым продолжает двигаться через Canvas2D.
- Вето пока кликают админы; вето самими капитанами на сайте — следующий шаг.

## Вето для капитанов

Отдельная страница `/veto.html`, капитаны банят и пикают сами.

1. В панели под вето — блок **«Вето для капитанов»**: формат, таймер (5 мин,
   3–15 или без таймера), язык сообщений капитанам (English по умолчанию) →
   **«Создать ссылки»** для выбранного матча. Или отдельная страница
   `/veto.html` (там же блок «Настройки вето» и **«Матч из расписания»** —
   команды подставятся сами).
2. Четыре короткие ссылки (~140 символов): каждому капитану — **в личку**
   в Discord, зрителям — куда угодно, **админская — только у нас**: только
   она показывает текст для HLTV.
   Сайт вето по умолчанию на английском, флаги EN/RU в шапке переключают
   язык (запоминается).
3. Монетку бросают сами капитаны, когда оба открыли ссылки: первый
   прячет свою случайную часть (отпечаток), второй добавляет свою, первый
   открывает — результат из обеих частей. Заранее его не знает никто,
   даже админ, который делал ссылки; подменить свою часть после чужой
   нельзя. Кто выиграл, решает, кто банит первым. Дальше по очереди:
   нажать карту → подтвердить. После пика соперник выбирает сторону.
4. На всё вето 5 минут — это просто счётчик, сайт за капитанов не ходит.
5. В конце — итог и кнопка «Скопировать для HLTV».

Ссылка капитана личная: в ней секрет, из которого растёт его ключ, — по
ней можно ходить за команду. В ссылках только отпечатки ключей; сами
ключи капитаны присылают на сайт, и чужой ключ с неверным отпечатком не
примут.
Чужую ссылку подделать нельзя — ход без подписи нужного капитана
просто не засчитывается. Сделанный ход назад не забрать: если капитан
попробует подписать другой ход на тот же шаг, у всех останется первый,
а сверху появится предупреждение — тогда решает админ. Зрители только
смотрят. Ошиблись или ссылка ушла не туда — создай новые
ссылки. Последние ссылки форма помнит в этом браузере.

## Букмекеры

Во вкладке «Лобби» блок **«Наш турнир у букмекеров»**: раз в 5 минут сайт
сам смотрит открытые линии букмекеров и показывает таблицу: слева все 16
лицензированных БК, сверху матчи ближайшего дня, в клетках коэффициенты на
победу (LIVE — если матч уже в лайве) и ↗ на событие. Как только у кого-то
открылась линия на наш матч, в журнале лобби появляется запись
(«OLIMPBET: открыта линия Honved Esport – Lavked (22:00), 2.20 · 1.62»).
Кнопка «Проверить сейчас» — без ожидания.

В клетке, кроме победы, — всё, что БК отдаёт в общей линии: фора (Ф1 — наша
первая команда) и тотал (ТБ/ТМ), размер линии (сколько исходов или рынков у
матча, как считает сама контора) и лайв: LIVE — сейчас, «был в лайве»,
«лайв заявлен». Если кэф сдвинулся, рядом кэф открытия. Слева у конторы —
сколько наших матчей в линии и самая большая линия.

- **Сводка** — копирует текст для чата: у кого турнир, по каждому матчу кэфы,
  открытие, размер линии, лайв и кто линию не дал.
- **CSV** — все линии за неделю (их помнит этот браузер): контора, матч,
  когда открылась линия, кэфы открытия и текущие, рынки, размер, лайв, ссылка.
  Открывается в Excel/Google Таблицах.

Автоматически проверяются те, у кого линия открыта без входа и капчи:
Фонбет, PARI, Bettery, 24bet, OLIMPBET, Марафон, Бетсити, Леон (список —
`BOOKMAKERS` в `bookmakers.js`). Остальные — строками со ссылкой ↗, смотреть
руками: Winline (только websocket), Зенит (нужен заголовок из браузера),
BetBoom и Лига Ставок (капча), Мелбет и БЕТ-М (ответы зашифрованы), Балтбет
и Спортбет (вчера линии не давали). Работает на Cloudflare/Netlify и в `server.js`
(функция `/api/bookmakers`); ключей не нужно. Если какая-то контора не
пускает зарубежные адреса Cloudflare, запусти панель локально
(`node server.js`) — тогда линии запрашиваются с твоего адреса.

## Лобби FACEIT

1. Ключ: developers.faceit.com → App Studio → своё приложение → API Keys →
   **Client side**. Лучше ограничить его сайтом панели.
2. Ключ сайта (рекомендуется): секрет `FACEIT_API_KEY` в настройках хостинга
   (Cloudflare Pages → Settings → Variables and Secrets → Add → Type: Secret;
   на Netlify — Environment variables). Ключ остаётся на сервере: в браузер
   он не уходит, скопировать его с сайта нельзя, а прокси `/api/faceit`
   отдаёт его данные только страницам самой панели. Тогда поле ключа в лобби
   можно не заполнять. Свой ключ в поле по-прежнему работает и важнее ключа сайта.
3. Во вкладке «Лобби» — ссылка на турнир
   (`https://www.faceit.com/ru/championship/<id>/…`) → «Следить».
   Если FACEIT не отдаёт турнир, подходит ссылка на комнату матча
   (`…/room/1-<id>`, можно несколько через пробел): лобби следит за матчем
   напрямую. Ошибка FACEIT показывается с его собственным текстом.
4. «Включить уведомления» и «Проверить звук» — один раз на компьютере.

Панель проверяет турнир каждые 20 секунд. Конец карты, конец матча и
статус FACEIT «пауза» — красная плашка «Принял», звук каждые 20 секунд
(до минуты; смолкает, как только вкладку открыли), уведомление системы, мигающий заголовок и
счётчик на вкладке «Лобби». Ключ и ссылка хранятся только в этом браузере.

- Сообщения игрокам: «Спасибо за игру» после матча и «Next xx:MM» —
  через 10 минут после конца (настраивается) с командами следующего
  матча из FACEIT или расписания. Пинги @ ставятся руками. Шаблоны
  правятся, подстановки {team1} {team2} {time} {score} {maps}.
- Тех. паузу FACEIT не сообщает: кнопка «Тех. пауза: команда» запускает
  таймер, «Продолжили» пишет длительность в журнал.
- Журнал (концы карт и матчей со счётом по картам, паузы) копируется
  целиком.
- Если браузер не пускает запросы к FACEIT напрямую, панель сама идёт
  через `/api/faceit` (Netlify и `server.js`).
- Фоновая вкладка: браузер может проверять реже, раз в минуту.

## OBS

- Исходный шаблон сохранён в assets/obs-template.json.
- При каждом экспорте создаются новые UUID и ссылки игроков.
- Камеры получают viewport 1920×1080, поворот 0°,
  нулевую обрезку и вписывание в сцену.
- Матрица содержит восемь маленьких и две большие плитки.
- Под каждой камерой лежит карточка игрока `CARD NN | Команда | Ник`
  (см. ниже): пока VDO.Ninja без видео, в кадре карточка.
- Имя файла сохраняет кириллицу и очищается от
  недопустимых символов.

Отображение внутри самого OBS требует отдельной проверки
на машине с OBS. Автотесты проверяют структуру JSON,
трансформации, ссылки, UUID и размеры матрицы.

## Карточка игрока вместо камеры

`card.html?team=Команда&nick=Ник` — кадр 1920×1080: фон ивента, логотип
и название команды, ник и фото игрока с HLTV. В OBS JSON она стоит
источником браузера прямо под камерой. Ссылка камеры содержит
`&cleanoutput&transparent`: пока игрок не подключился или отвалился,
VDO.Ninja ничего не рисует и видна карточка. Подключился — камера
закрывает её целиком. Если вебка не 16:9 (4:3, телефон вертикально),
по бокам будут видны края карточки.

- Адрес карточек берётся с сайта, где открыта панель
  (oneshot-panel.pages.dev, свой домен, локальный сервер). Артефакт Claude
  своего сайта не имеет и ставит https://oneshot-panel.pages.dev.
- Фон: `assets/card/background.jpg`, 1920×1080, JPEG q90: утверждённый яркий
  бирюзовый дизайн CyberClash. Логотип турнира — отдельный слой.
  Цвета текста и акцента — токены `--card-*` в начале `card.css`.
- Фото: `assets/players/players.json` — игроки из листа
  «Teams (Group Stage)» таблицы организатора со ссылками на HLTV.
  `photo` — вырезанное фото с HLTV (bodyshot, 400 px в ширину),
  `file` — скачанный файл рядом. Скачать или докачать:
  `python3 scripts/fetch_player_photos.py` (нужен доступ к
  img-cdn.hltv.org). Ник сверяется без учёта регистра, пробелов
  и знаков; другое написание ника — в `aliases`.
- Нет фото (на HLTV силуэт или ещё не скачано) — на месте фото логотип
  команды; нет и логотипа — только текст.
- Фото принадлежат HLTV.org.

## Браузерная проверка

```
python3 scripts/qa_browser.py --url http://127.0.0.1:3000
python3 scripts/qa_live.py --url http://127.0.0.1:3000
python3 scripts/qa_veto_site.py --url http://127.0.0.1:3000
```

- `qa_live.py`: вкладки, статус вебок, OBS напрямую и через док,
  копирование JSON, оверлей вето и лобби — VDO.Ninja, obs-websocket и
  FACEIT подменены, время лобби ускорено.

- `qa_obs_runtime.py`: официальный OBS 32.2.2, настоящий браузерный источник
  CEF и настоящий VDO.Ninja. Проверяет доставку ручных ходов, подтверждение
  источника, движение дыма, анимации карт и восстановление после перезагрузки.
  Только Sheets подменены. Запускается workflow «OBS runtime regression» в PR.
- Нужны Python, Playwright и Chromium.
- Путь Chromium: --chromium.
- По умолчанию используются синтетические ответы Sheets.
- Для реальных сохранённых ответов:
  --roster /path/roster.json --schedule /path/schedule.json
- Это проверяет приложение на этих данных, но не доказывает
  прямое HTTPS-соединение Chromium с Google.
- TLS и CSP остаются включёнными.
- Результаты и скриншоты сохраняются в artifacts/.

## Карточки CyberClash и фотографии в OBS

По умолчанию сайт скачивает JSON без карточек. Галочка
«Добавлять карточки и заглушки под камеры» рядом со скачиванием включает
их для текущего экспорта; после нового открытия панели она выключена.
С включённой галочкой каждая сцена игрока содержит CARD под камерой CAM.
CARD открывает `card.html?team=…&nick=…` на том же сайте, откуда скачали JSON
(для Claude-артефакта — на oneshot-panel.pages.dev).
Фон, логотип турнира, фото, эмблема команды и ник — отдельные слои.
С фото портрет расположен крупно по центру; без фото или при ошибке его
загрузки показываются эмблема команды и крупный ник.
Чужое фото по совпавшему нику из другой команды не подставляется.

Перед публикацией Netlify запускает:
`python3 scripts/fetch_player_photos.py --allow-missing`.
Проверенные фотографии и заполненные file хранятся в assets/players/ в Git.
Загрузчик использует эти файлы повторно и докачивает недостающие;
опубликованный players.json содержит только подготовленные имена файлов. Поэтому во
время эфира карточка обращается к нашему сайту, а не к HLTV.
Неудачные загрузки и игроки без ссылки на фото используют заглушку.
Новый игрок без записи в каталоге также получает заглушку до добавления
его HLTV-профиля/ссылки на фото в assets/players/players.json.

Для собственного сервера запустите загрузчик перед копированием файлов.
Для строгой проверки загрузки используйте его без --allow-missing;
--force обновляет уже скачанные изображения.
Сайт остаётся статическим; Python нужен только для подготовки файлов.

CI готовит тот же public/, запускает Node и Python проверки, браузерный
QA панели и все карточки каталога. Артефакт oneshot-panel-site содержит
готовые файлы публикации; panel-browser-qa — скриншоты, пример OBS JSON
и player-cards-report.json с числом фото и заглушек.
Сам импорт и поведение камеры в OBS проверяются на эфирном компьютере.

## Эфирный пакет на игровой день

В GitHub Actions откройте **Match day broadcast package → Run workflow** и
укажите дату DD.MM в расписании текущего сезона. Пары и основные пятёрки
читаются из актуальных таблиц; неизвестные пары не придумываются.

- Артефакт **CyberClash-DD.MM-2026-OBS**: четыре готовых коллекции для
  15 октября (для другой даты — её подтверждённые матчи). Каждая CARD
  содержит готовую картинку прямо в data-документе браузера: фотографии,
  фон, подписи и заглушки не требуют сайта или локальных путей.
- Полный пакет: JPG 1920×1080, исходные фото, оформление, превью матчей,
  тексты игрокам и обсерверу, обычные онлайн-коллекции и запасные
  коллекции с локальными image_source. Последние подготавливаются после
  распаковки PREPARE_WINDOWS.cmd или python3 prepare_local.py.
- Все встроенные CARD открываются в Chromium с отключённой сетью.
  Проверяются оба способа подготовки путей; пути машины CI не попадают
  в архив. Перед эфиром оператор проверяет импорт и реальные камеры в OBS.

Снимки исходных таблиц в Git не сохраняются. Подготовленные файлы фото
хранятся в Git, чтобы статическая публикация не оставляла file пустым.
Старые записи Aces сохранены рядом с актуальными Black Phoenix;
чужие фотографии по совпавшему нику не используются.

# Утренний запуск: Oneshot Panel + eBot (37.230.228.105)

Прочти это один раз — дальше 15 минут руками. Всё уже написано и протестировано
(299 юнит-тестов; чтение списка/статистики/хитмапы проверено живьём против
твоего eBot; управление и консоль — на моках, ключевые кнопки проверишь ты,
живьём, по чек-листу внизу).

## Что ты получишь

Открыв `https://panel.<домен>/` (или `http://<ip>:3000`, пока без домена):
- **Лобби → «Матчи eBot»**: список матчей с живым счётом (обновление 20 с),
  кнопки на живом матче: Пауза, Стоп, Стоп без RS, Конец разминки, ножи,
  возврат в разминку, **Консоль** (логи сервера + чат + RCON + писать в чат),
  **Статистика** (таблица игроков с сортировкой + хитмапа на радаре карты).
- **Создание матча** прямо из панели (команды, карта, сервер из списка eBot).

## Шаг 1. Подготовь eBot (5 мин, на 37.230.228.105)

```sh
ssh root@37.230.228.105
```

**ОБЯЗАТЕЛЬНО** (сейчас секрет WebSocket — дефолтный `ebotv3`, это дыра):

1. Сгенерируй новый секрет:
   ```sh
   openssl rand -hex 32
   ```
2. Задай его в ДВУХ местах (одинаковую строку!):
   - `/home/ebot/ebot-cs2-app/config/config.ini` → `WEBSOCKET_SECRET_KEY = "<новый>"`
   - `/home/ebot/ebot-cs2-web/config/app_user.yml` → `websocket_secret_key: '<новый>'`
3. Проверь, что MySQL-пароль eBot не `ebotv3` (в config.ini секция [BDD] и в
   `/home/ebot/ebot-cs2-web/config/databases.yml` — если дефолтный, смени и там
   и там; пользователям eBot это ничего не ломает, это внутренние креды).
4. Перезапусти:
   ```sh
   service ebot-cs2-app restart && service ebot-cs2-logs restart
   ```
5. Проверка: `service ebot-cs2-app status` — active. Открой
   `http://37.230.228.105/` — список матчей по-прежнему виден (он публичный,
   секрет его не закрывает — и не должен).

**Учётка для панели**: заведи в eBot отдельного пользователя-судью
(`/admin.php` → Users → Create: username `oneshot`, пароль сложный,
is super admin — можно оставить, меньше прав — отдельная тема). Именно его
креды пойдут в панель, не твой главный админ.

## Шаг 2. Подними панель (10 мин, на ТОМ ЖЕ сервере)

Всё по `deploy/README.md`, короткая версия:

```sh
# Node.js 22
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt-get install -y nodejs

# Код
sudo useradd -r -s /usr/sbin/nologin oneshot || true
sudo git clone -b feat/ebot-admin https://github.com/ssolutionn/Oneshot-Panel.git /opt/oneshot-panel
sudo chown -R oneshot:oneshot /opt/oneshot-panel
cd /opt/oneshot-panel && sudo -u oneshot npm test    # 299 pass = ок

# Секреты
sudo tee /etc/oneshot-panel.env >/dev/null <<'EOF'
EBOT_URL=http://127.0.0.1/
EBOT_USER=oneshot
EBOT_PASSWORD=<пароль судьи из шага 1>
EBOT_ADMIN_OPEN=1
EOF
sudo chmod 600 /etc/oneshot-panel.env && sudo chown root:oneshot /etc/oneshot-panel.env
```

⚠️ **EBOT_URL=http://127.0.0.1/** — панель на одном сервере с eBot, ходит в
него локально (пароль не гуляет по интернету). Порт 12360 (socket.io) тоже
локальный. Из интернета наружу торчит только порт панели.

```sh
# Сервис. ⚠️ ВАЖНО: в юните ОБЯЗАТЕЛЬНО убери # у строки EnvironmentFile= —
# без неё секреты из /etc/oneshot-panel.env не подхватятся, панель
# поднимется, но кнопок/консоли НЕ БУДЕТ (молча, только монитор).
sudo cp deploy/oneshot-panel.service /etc/systemd/system/
sudo nano /etc/systemd/system/oneshot-panel.service   # убрать # у EnvironmentFile (критично!)
sudo systemctl daemon-reload && sudo systemctl enable --now oneshot-panel
sudo systemctl status oneshot-panel
```

Пока без nginx/домена: в юните `/etc/systemd/system/oneshot-panel.service`
**раскомментируй строку `#Environment=HOST=0.0.0.0`** (панель слушает не
только локальный) и `sudo systemctl restart oneshot-panel`, затем фаервол
(`sudo ufw allow 3000`, лучше с ограничением по своему IP: `sudo ufw allow
from <твой-ip> to any port 3000`) и зайти `http://37.230.228.105:3000/`.
⚠️ С `HOST=0.0.0.0` эндпоинты управления eBot открыты без авторизации —
только своя сеть/VPN, или ставь `EBOT_ADMIN_TOKEN` (см. deploy/README.md).
HTTPS и домен — потом, по `deploy/README.md` (nginx-конфиг готов; за nginx
верни HOST=127.0.0.1).

## Шаг 3. Чек-лист живьём (5 мин) — ГЛАВНОЕ

Открой панель → вкладка **Лобби**:

| # | Что делаешь | Что должно быть |
|---|---|---|
| 1 | Блок «Матчи eBot» | видны матчи с eBot, счёт тикает |
| 2 | На живом матче кнопки | есть «Пауза ⏯», «Стоп», «Консоль», «Статистика» |
| 3 | **«Статистика»** | диалог: таблица игроков (К/А/D/K-D/HS%), таб «Хитмапа» — точки на радаре |
| 4 | **«Консоль»** | пошли строки лога CS2; в чате — сообщения игроков |
| 5 | В консоли: переключатель «в чат», написать `test` (латиницей — кириллицу фильтр чата пока не пускает) | в игре в чате появится `test` от сервера |
| 6 | В консоли: RCON-режим, `status` | ответ сервера в блоке RCON |
| 7 | **«Пауза ⏯»** на живом матче | журнал лобби: «команда принята»; в игре пауза |
| 8 | Ещё раз — пауза снимется | |
| 9 | Форма «Новый матч» внизу блока | списки карт и серверов из eBot; создать → в списке появится |

Если что-то из 1–3 не работает — смотри `journalctl -u oneshot-panel -n 50`
и проверь `/etc/oneshot-panel.env`. Если 4–9 — смотри шаг 1 (секреты eBot
совпадают в двух файлах?) и креды судьи (войти ими руками в
`http://127.0.0.1/admin.php` на сервере).

## Известные границы

- Консоль и хитмапа «не для anubis/vertigo/ancient»: радары этих карт у eBot
  нет — панель показывает нашу миниатюру с пометкой «приблизительно».
- `say_team` в чат не читается (только общий чат) — так же, как у самого eBot.
- Мониторинг (список матчей, статистика, хитмапа) работает вообще без кредов;
  кнопки/консоль/создание — только с EBOT_USER/EBOT_PASSWORD.
- Опционально: `EBOT_ADMIN_TOKEN` (sha256 от фразы) в env — тогда каждый POST
  управления требует заголовок-токен; для локальной сети не обязателен.

## Прочее, что важно знать

- **Консоль матча** (логи/чат/RCON) работает только на своём server.js —
  на Netlify/Cloudflare её нет (SSE не живёт в serverless). Статистика и
  хитмапа работают везде.
- **EBOT_ADMIN_TOKEN не ставь** для локального/VPN-деплоя: панель пока не
  умеет вводить токен в браузере — с заданным токеном UI-кнопки станут
  read-only (токен — для curl). Это в планах.
- Split-деплой (панель НЕ на сервере eBot): открой наружу TCP 12360 и
  помни — пароль админки пойдёт по HTTP. Лучше один сервер или VPN.
- nginx + certbot с нуля: до выпуска первого сертификата закомментируй
  443-блок (или `certbot certonly --standalone -d <домен>` до `ln -s`),
  иначе reload не пройдёт — пути сертификатов ещё не существуют.

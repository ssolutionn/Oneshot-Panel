# Автотестирование через агентов: концепция

Документ отвечает на вопрос «как агент (Claude Code, Codex, DSH) проверяет панель
перед пушем и после правки», а не «какие тесты у нас есть». Проверки уже есть:
27 файлов `node:test`, 18 браузерных `scripts/qa_*.py`, 14 workflow, `npm run check`,
`check:veto-sync`, пересборка артефакта. Не хватает не покрытия, а **процедуры
выбора, запуска и разбора** — её и описываем.

Коротко:

- тесты остаются единственным источником истины, агент их **не заменяет** и не судит;
- у человека, CI и агента один вход (`npm run verify`) и один машинный отчёт;
- скрипт знает «как проверить», скилл — «когда и что делать с результатом»;
- дешёвое раньше дорогого: T0 (секунды) → T1 (минуты) → T2 (ночь);
- отдельно защищаемся от главного провала агента — «сделал зелёным, ослабив тест».

**Статус: фаза 0 внедрена.** Пульт — `scripts/agent-test.mjs`, реестр —
`scripts/agent/suites.json`, обёртка сценариев — `scripts/agent/run_qa.py`,
согласованность держит `test/agent-registry.test.js`. Скиллы —
`.claude/skills/verify-change` и `.claude/skills/triage-failure`; остальные из
таблицы §3.3 появятся в фазах 2–3.

## 1. Проблема

Сегодня агенту, чтобы ответить «я ничего не сломал», нужно:

1. угадать, какие из 45+ проверок относятся к диффу (в AGENTS.md написано, что
   проверять, но не чем и в каком порядке);
2. поднять сервер, браузер, Python, иногда OBS — и не забыть погасить;
3. прочитать вывод, где смешаны `PASS:`-строки, трейсы Playwright и шум CSP;
4. отличить регрессию от флака, отсутствующего Chromium и упавшей сети.

Каждый шаг — место, где модель ошибается по-разному в каждом заходе. Отсюда
главная цель: **вердикт должен быть функцией от диффа, а не от настроения агента**.

Не-цели:

- не писать свой тестовый фреймворк и не добавлять npm-зависимости (правило
  проекта); пульт — тонкая обёртка над существующими командами;
- не отдавать модели криптографию вето, точные строки HLTV, CSP и геометрию —
  это проверяет код;
- не гонять в PR сеть, настоящий VDO.Ninja и OBS — для них ночной контур T2;
- не привязываться к одному агенту: ядро — скрипты и AGENTS.md, скиллы — тонкие
  адаптеры конкретной оболочки.

## 2. Принципы

1. **Скрипт — детерминизм, скилл — суждение.** Всё, что можно записать командой,
   живёт в `scripts/`; в скилле остаются маршрутизация, стоп-условия и разбор.
   Скилл длиннее двух экранов — значит, это скрипт.
2. **Один вход.** `npm run verify` — то же самое локально, в CI и у агента.
   Разные пути запуска = разные результаты = недоверие к гейту.
3. **Отчёт — данные.** Агент читает `report.json`, а не `PASS:`-строки. Текст
   остаётся для человека.
4. **Тест — спецификация.** Правка `test/**` и `scripts/qa_*` — отдельное
   решение с обоснованием, а не побочный эффект починки.
5. **Нет доказательства — нет диагноза.** Падение без trace/скриншота/лога —
   это `error`, а не `fail`, и лечится окружением, а не кодом.
6. **Дешёвое раньше дорогого.** T0 всегда, T1 по карте риска, T2 — ночью и по
   требованию. Первый провал нужного уровня останавливает веер.
7. **Офлайн по умолчанию.** Моки Sheets/VDO/OBS/FACEIT — не компромисс, а
   преимущество: агент получает воспроизводимость, которой нет у живого эфира.

## 3. Четыре слоя

```
скиллы            когда проверять, как читать, когда остановиться
  ↑
пульт             выбор по диффу, запуск, шарды, сводка   scripts/agent-test.mjs
  ↑
приборы           существующие проверки + единый отчёт    test/, scripts/qa_*
  ↑
оркестрация       субагенты на шарды, workflow, PR-комментарий
```

### 3.1. Приборы

Ничего не переписываем. Каждая проверка получает контракт:

- вход: путь к серверу (или сама его поднимает), `--artifacts <dir>`;
- выход: код возврата и `report.json` рядом с артефактами;
- `--list` у пульта; выбор одного сценария внутри `qa_*` — фаза 1.

Для `node:test` это уже почти есть (`--test-name-pattern`, TAP). Для Python —
обёртка `scripts/agent/run_qa.py`: запускает сценарий, собирает `PASS:`-строки,
хвост ошибки и класс «окружение или провал», пишет JSON. Постепенно `--json`
появляется и в самих `qa_*.py`; обёртка остаётся совместимой с уже написанными.

### 3.2. Пульт

`scripts/agent-test.mjs` + реестр `scripts/agent/suites.json`. Умеет:

- по умолчанию выбрать проверки по `git diff --name-only` и карте риска (§5);
- `--tier T0|T1|T2`, `--only <suite>`, `--all`, `--base <ref>`, `--dry-run`,
  `--list`, `--json`, `--url` (готовый сервер вместо своего);
- поднять `server.js` на свободном порту, дождаться готовности, погасить в `finally`
  (в том числе на Windows, где процессы любят оставаться);
- разложить артефакты по `artifacts/agent/<runId>/<suite>/`, не затирая прошлые;
- свести всё в `report.json` и короткий `index.md` для человека;
- вернуть код: `0` зелёно, `1` провал, `2` окружение (`3` — резерв под флак).

Интерфейс (добавлен в `package.json`):

```sh
npm run verify                       # T0 + T1 по рабочему дереву
npm run verify -- --tier T0          # быстро: синтаксис и unit-тесты
npm run verify -- --base origin/main # по диффу с базой
npm run verify -- --dry-run          # что выбрано и что осталось без проверки
npm run verify -- --only browser-veto-site   # одна проверка (для отладки)
npm run verify -- --tier T2 --all    # ночной контур
npm run verify -- --list
node scripts/agent-test.mjs --json                 # отчёт в stdout, сводка в stderr
node scripts/agent-test.mjs --json --only browser-panel
```

`--json` печатает в stdout только отчёт, поэтому для машинного разбора зовите
сам пульт: `npm` добавляет в stdout свою шапку `> node …`.

Проверки идут последовательно (шарды — фаза 1), сервер поднимается на
свободном порту и гасится в `finally`. Дочерние процессы пишут в файлы, а не
в pipe: в песочнице Windows именованные каналы запрещены, а в CI это ничего
не меняет.

### 3.3. Скиллы

Каталог `.claude/skills/<name>/SKILL.md` (Claude Code), тот же текст читается
Codex и DSH как обычная инструкция. Каждый скилл — про **решение**, не про
синтаксис Playwright. Минимальный набор:

| Скилл | Когда | Что делает | Чем заканчивается |
|---|---|---|---|
| `verify-change` — есть | перед любым пушем/PR | `git diff` → карта → `npm run verify` | вердикт + список непроверенного |
| `triage-failure` — есть | гейт красный | классифицирует падение по §6, предлагает минимальный эксперимент | класс + следующий шаг |
| `browser-qa` | правка интерфейса | гоняет нужный `qa_*.py`, смотрит скриншоты | отчёт по сценариям |
| `veto-regression` | правка вето/реле/оверлея | node-тесты + сайт вето + сборка копии | зелёный `check:veto-sync` |
| `visual-review` | изменился вид | дифф скриншотов считает скрипт, агент объясняет | список подозрительных мест |
| `release-check` | релиз/деплой | сборка сайта, артефакт, заголовки, публикация | чек-лист с доказательствами |
| `test-author` | найден баг | баг → сценарий на существующих моках | новый тест + запись в карту |

Остальные скиллы (без пометки) — фазы 2–3; до них их роль выполняет пульт с
`--only` и `--dry-run`.

Правила для скиллов:

- только точные команды и пути, никаких «запусти подходящие тесты»;
- явные стоп-условия (окружение, сеть, время, секрет в выводе);
- ссылка на схему отчёта, а не пересказ вывода;
- «чего не делать» — обязательный раздел.

### 3.4. Оркестрация

- **Субагент = шард.** Родитель делит выбранные suites, каждый ребёнок получает
  готовую команду и обязан вернуть JSON, а не прозу. Родитель не пересказывает
  вывод, а агрегирует вердикты.
- **Веер по сценариям** (`workflow`-скрипт): suites × браузеры, независимые
  элементы, барьер только на сборке отчёта. Параллелизм ограничен: два браузера
  на 4 ГБ, OBS-сценарии — по одному.
- **PR-комментарий**: вердикт, упавшие сценарии со ссылкой на артефакты, что не
  запускалось и почему, какие проверки пропущены по карте.
- **Ночь**: T2 (настоящий VDO, OBS/CEF, WebKit, Cloudflare workerd), мутационная
  проба, обновление визуальных базлайнов.

## 4. Контракт отчёта

```json
{
  "version": 1,
  "run": { "id": "20261025-0109-a1b2", "tier": "T1", "startedAt": "2026-10-25T01:09:27.000Z", "durationMs": 214000, "command": "--tier T1" },
  "env": { "node": "v22.14.0", "python": "python3", "playwright": true, "browser": "chromium", "os": "linux" },
  "selection": {
    "all": false, "base": null,
    "changed": ["veto.js"],
    "unmatched": [],
    "selected": ["browser-veto-site"]
  },
  "suites": [
    {
      "id": "browser-veto-site",
      "title": "Сайт вето капитанов (отдельные браузеры)",
      "tier": "T1",
      "status": "fail",
      "durationMs": 187000,
      "scenarios": [
        { "id": "coin-toss", "status": "pass" },
        { "id": "forged-move", "status": "fail" }
      ],
      "evidence": ["artifacts/agent/20261025-0109-a1b2/browser-veto-site/forged-move.png"],
      "cmd": "python scripts/qa_veto_site.py --url {url} --artifacts {artifacts}",
      "reason": "упали: forged-move",
      "error": "…"
    }
  ],
  "summary": { "pass": 0, "fail": 1, "skip": 0, "error": 0 },
  "verdict": "fail"
}
```

`summary` считает **проверки**, а не шаги внутри них: один красный сценарий
делает красной всю проверку.

Правила, на которых держится автоматика:

- `skip` без `reason` — это `error`: молча пропущенная проверка хуже красной.
- `evidence` — только относительные пути внутри `artifacts/agent/<runId>/`.
- Секреты вычищаются на записи: ключ FACEIT, пароли OBS/комнат, `.cs2-data/token`,
  содержимое `#k=`/`#v=` не попадают в отчёт и логи.
- Коды возврата: `0` — зелёно, `1` — провал, `2` — окружение (`3` оставлен под
  флак-подозрение). Агент обязан различать 1 и 2: «нет Chromium» — не регрессия.

## 5. Карта риска

Реестр `scripts/agent/suites.json` — единственный список проверок (чтобы новый
сценарий нельзя было забыть, тест сверяет: каждый `scripts/qa_*.py` и каждый
`test/*.test.js` присутствует в реестре).

```json
{
  "browser-veto-site": {
    "title": "Сайт вето капитанов (отдельные браузеры)",
    "tier": "T1",
    "kind": "python-qa",
    "script": "scripts/qa_veto_site.py",
    "args": ["--url", "{url}", "--artifacts", "{artifacts}"],
    "needs": ["python", "playwright"],
    "timeoutMs": 1200000,
    "server": true,
    "select": ["veto.html", "veto.js", "veto.css", "veto-room.js", "assets/veto-*", "scripts/qa_veto_site.py"]
  }
}
```

`kind`: `command` (готовая команда), `node-test` (файлы `test/*.test.js`,
запускаются по одному процессу на файл), `python-qa` (`qa_*.py` через
`run_qa.py`). `needs` — обязательное (нет → `error`/код 2), `optionalNeeds` —
нет → `skip` с причиной. `skipUnlessEnv` — проверка включается, только если
задана переменная (например `VETO_SYNC_DIR`).

Выбор по диффу:

| Изменено | Что выберется сверх T0 |
|---|---|
| `core.js`, `index.html`, `style.css`, `app.js`, `theme.js` | `browser-panel`, `browser-cards`, `browser-camera`, `artifact-build`, `artifact-drift` |
| `veto*.js`, `veto.html`, `veto.css`, `assets/veto-short-*`, `server/veto-relay-*` | `browser-veto-site`, `veto-build`, `veto-sync` (если задан `VETO_SYNC_DIR`) |
| `assets/veto-overlay/**` | `browser-veto-overlay`, `veto-build` |
| `obs.js`, `vdo.js`, `obs-bridge.*`, `assets/obs-qr.js` | `browser-live`, `browser-qr`; `t2-*` — только ночью |
| `live.js`, `lobby.js`, `faceit.js`, `netlify/functions/faceit.mjs` | `browser-live` |
| `lan*.js`, `events/**`, `assets/lan-*` | `browser-lan` |
| `bookmakers.js`, `bookies.js`, `netlify/functions/bookmakers.mjs`, `assets/bookmaker-*` | `browser-bookies`; `t2-bookies-api` — ночью |
| `server/**`, `functions/**`, `_headers`, `netlify.toml`, `server.js` | T0 `unit-server` (заголовки и статика) |
| `cs2.js`, `server/cs2-*` | `browser-cs2` |
| `scripts/build-veto-site.mjs`, `claude-artifact/**` | `artifact-build`, `artifact-drift`, `veto-build` |
| `scripts/agent*`, `test/agent-registry.test.js`, `package.json` | T0 `unit-agent` |
| `scripts/check-syntax.mjs` | T0 `syntax` |
| всё остальное, что не подошло | T0 + предупреждение `нет проверок для: …` |

Карта живёт рядом с кодом и меняется в том же PR, что и файл, которого она
касается; устаревшая карта — это тихо пропущенная проверка.

## 6. Таксономия падений

| Признак | Класс | Что делает агент |
|---|---|---|
| падает только сценарий, затронутый диффом | регрессия | чинит код, не тест |
| падает сценарий вне диффа, но стабильно 2/2 | дрейф контракта | читает AGENTS.md «Что нельзя ломать», сверяет строки |
| `playwright`/Chromium/Python отсутствуют, `ECONNREFUSED` | окружение | стоп, код 2, инструкция человеку |
| падает 1/2, проходит при повторном порядке | флак | карантин §7, не правит assert |
| падает assert внутри мока (VDO/Sheets) | поломка прибора | чинится `scripts/qa_*`, отдельным PR |
| падение без trace/скриншота | нет доказательства | `error`, повтор с `--only` и `--verbose` |

## 7. Защита от самообмана

Главный риск агентного тестирования — не пропущенный баг, а **тихое ослабление
спецификации**. Поэтому:

- **Test-diff gate (фаза 2).** Любая правка `test/**`, `scripts/qa_*`, `scripts/agent/**`
  требует второго взгляда: отдельный субагент-ревьюер отвечает на один вопрос —
  «стало ли утверждение слабее?». Запрещено без issue: удалять assert, менять
  ожидаемую строку вслед за продуктом, добавлять `skip`/`retry`, расширять
  допуски. Если код не менялся, а тест — менялся, это красный флаг.
- **Карантин флаков (фаза 2)** — `docs/agent-testing/flakes.json`:
  `{ "scenario": "qa_live/late-viewer", "owner": "…", "issue": "…", "expires": "2026-11-30", "reason": "…" }`.
  Просроченная запись валит гейт: карантин — долг, а не режим.
- **Правило доказательства.** `fail` без артефакта превращается в `error`;
  отчёт без `evidence` не считается диагнозом.
- **Секреты.** Редакция на записи отчёта; `#k=`/`#v=` и пароли не логируются;
  публикация артефактов — только внутри репозитория/CI.
- **Никакой сети в T0/T1.** Если сценарию нужен интернет, он живёт в T2 и
  помечен `needs: ["network"]` — тогда его отсутствие не выдаётся за провал.
- **Локаторы только документированные.** В AGENTS.md перечислены `id` и
  `data-`атрибуты; «самовосстанавливающиеся» локаторы по тексту запрещены — они
  превращают регрессию в зелёный прогон.

## 8. Где LLM действительно добавляет ценность

Детерминированные проверки агент только запускает. Польза модели — там, где
нужен смысл:

1. **Исследовательские проходы.** Цель + ограничения («как оператор делает вето
   BO3 за 40 секунд»), агент проходит сценарий в живом браузере, фиксирует шаги.
   Найденный дефект превращается в новый сценарий `qa_*`, а не в устный вывод.
2. **Визуальное ревью.** Пиксельный дифф считает скрипт; агент объясняет, что
   именно поехало (переполнение, контраст, обрезанный ник) и где это в CSS.
3. **Триаж.** Группировка падений, отделение флака от регрессии, гипотеза и
   минимальный эксперимент вместо «попробую ещё раз».
4. **Автор тестов.** Из баг-репорта или лога эфира — сценарий на существующих
   моках; отдельно проверяется, что он падает на старом коде.
5. **Мутационная проба.** Агент в отдельном worktree вносит точечные мутации в
   контракты (`Map was left over`, сторона соперника, CSP-директива, порядок
   карт) и смотрит, краснеют ли тесты. Отчёт — «дыры в спецификации», а не
   «агент сломал код».
6. **Разбор инцидента.** Скриншот/лог из эфира → сценарий, воспроизводящий
   проблему, с теми же моками.

Чего не делаем: не просим модель решать, «правильная ли подпись хода», не
сравниваем строки HLTV «на глаз», не доверяем ей подсчёт очков и сторон.

## 9. Протокол работы агента

**До:**

1. `git status` + `git diff --stat` → карта §5.
2. Объявить план: какие suites, какой tier, что останется непроверенным.
3. T0 всегда: `npm run check` + `npm test` (+ python unittest при правке
   `test/*_test.py`).

**Во время:**

- гонять только выбранное; полный T2 — никогда в PR-цикле;
- правки кода и правки тестов — разными шагами, чтобы diff читался;
- окружение сломалось → стоп (код 2), не «добьём зелёным любой ценой».

**После:**

1. Упавший сценарий перезапускается ровно один раз (`--only`) для отделения флака.
2. Починили — сначала упавший сценарий, затем весь выбранный набор, затем T0.
3. Готово = зелёный отчёт **и** пройденный test-diff gate; в ответе — вердикт,
   артефакты, что не проверялось и почему.

Стоп-условия: два одинаковых падения по окружению; больше 20 минут T1 без
прогресса; в выводе засветился секрет; для проверки требуется сеть.

## 10. Метрики

- время до вердикта: T0 p50 < 20 с, T1 p50 < 5 мин на типичный дифф;
- flake rate: доля сценариев, меняющих вердикт без изменения кода (< 2 %);
- доля падений с evidence (цель 100 %);
- mutation score по `core.js`, `veto-room.js`, `obs.js` — сколько контрактных
  мутаций ловят тесты;
- «побеги»: баги в эфире после зелёного гейта (главная метрика, всё остальное —
  прокси);
- стоимость: токены и минуты на PR.

## 11. Внедрение

Каждая фаза полезна сама по себе и не ломает текущие команды.

| Фаза | Что появляется | Критерий готовности |
|---|---|---|
| 0. Пульт — **внедрено** | `suites.json`, `agent-test.mjs`, `run_qa.py`, `report.json`, скиллы `verify-change` и `triage-failure`, `npm run verify` | одна команда даёт одинаковый JSON локально и в CI; агент не угадывает suites |
| 1. Выбор — частично | выбор по диффу и карта риска есть; остались шарды и выбор одного сценария внутри `qa_*` | T1 на типичный дифф ≤ 5 мин; неизвестный путь виден в отчёте |
| 2. Разбор | карантин флаков, test-diff gate, отчёт в PR | каждое падение классифицировано; просроченный карантин красный |
| 3. Смысл | `visual-review`, исследовательские проходы, `test-author` | найденный дефект становится сценарием, а не сообщением в чат |
| 4. Ночь | T2 (VDO/OBS/WebKit/Cloudflare), мутационная проба, PR-комментарий | утренний отчёт отвечает «что сломалось и где», без чтения логов |

## Приложение A. Скилл `verify-change`

Живёт в `.claude/skills/verify-change/SKILL.md`; здесь — его суть, чтобы
Codex и DSH читали то же самое из документа.

```markdown
## Когда
Перед коммитом/пушем и после каждой правки, которая может задеть поведение.

## Шаги
1. `git status --short && git diff --stat` — зафиксировать изменённые файлы.
2. `npm run verify -- --dry-run` — что выбрано и что осталось без проверки.
3. `npm run verify` (быстро — `--tier T0`) → `artifacts/agent/<runId>/report.json`.
4. Красное → скилл `triage-failure`; зелёное → проверить `summary.skip`
   и `selection.unmatched`.

## Чтение отчёта
- `verdict` — единственный источник вердикта, не текст в консоли;
- `summary.skip` с `reason` — перечислить человеку;
- `evidence` — приложить пути, не пересказывать скриншоты.

## Стоп
- `env` (код 2) — не чинить код, сообщить чего не хватает;
- засветился секрет — остановиться и вычистить артефакты.

## Не делать
- не править `test/**` и `scripts/qa_*` в том же шаге, что и код;
- не запускать T2 и сетевые сценарии в PR;
- не добавлять `skip`/`retry`, чтобы получить зелёное.
```

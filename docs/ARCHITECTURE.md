# Oneshot: структура на много событий и много операторов

Статус: **проект структуры**. Фаза 1a уже в репозитории: схема манифеста с проверкой
(`events/schema.js`), манифест КиберКлэша (`events/cyberclash/event.json`), шаблоны
(`events/_templates/`) и тесты-контракты (`test/events.test.js`), которые падают, если манифест
разойдётся с тем, что зашито в коде. Приложение манифесты пока **не читает** — это следующие фазы (раздел 9).
Сейчас панель — один турнир (CyberClash), у которого всё зашито в код; режим «ЛАН» — первая заплатка
в сторону «много событий». Здесь описано, как это устроить правильно.

Для дизайнеров: ТЗ по каждой поверхности лежат в [docs/design/](design/README.md).

## 1. Принципы

1. **Продукт один, событий много.** Код общий. Всё, что отличается от турнира к турниру
   (название, бренд, откуда составы, какие вкладки нужны, настройки вето), живёт в
   *пакете события*, а не в коде.
2. **Событие создаётся без программиста.** Оператор берёт шаблон, меняет название и цвета,
   кладёт логотип. Код трогают только когда нужна новая возможность.
3. **События не мешают друг другу.** Свои настройки, свои камеры, свои фото, своё состояние
   в браузере. Открыл другое событие — ничего от прошлого не просочилось.
4. **Хранилище прячется за интерфейсом.** Сегодня события лежат в репозитории и в браузере,
   завтра в облаке — код вкладок этого не заметит.
5. **Каждый шаг миграции не меняет поведение КиберКлэша.** Тесты зелёные до и после.

## 2. Сущности

```
Oneshot (внутренний продукт)
 ├─ Событие (турнир, ЛАН, лига)          slug · название · бренд · модули · источник данных · операторы
 │    ├─ Матч (состав, камеры, вето)     живёт у оператора, пока идёт матч
 │    └─ Ресурсы                          логотипы, фото игроков, фоны
 └─ Модули (общий код)                    вебки/OBS · вето · карточки · лобби FACEIT · букмекеры · сервер CS2 · ЛАН
```

- **Событие** — единица всего. У него `slug` (`cyberclash`, `winter-lan`), он же основа ссылок
  капитанов (`/winter-lan_team`).
- **Модуль** — вкладка со своей логикой. Событие включает нужные (на ЛАНе нет FACEIT и букмекеров).
- **Бренд-кит** — логотип, цвета, шрифт, фон. Один на событие, его читают все поверхности
  (карточка, оверлей, страница вето).
- **Роли**: `admin` (создаёт и правит события, добавляет людей), `operator` (ведёт матчи конкретного
  события), `viewer` (смотрит, например режиссёр).

## 3. Карта сайта (адреса)

| Адрес | Что это | Доступ |
|---|---|---|
| `/` | Выбор события: список доступных тебе, «Новое событие» | вход |
| `/e/<slug>/` | Рабочее место события: Подготовка, Вето, OBS, Сервер, Лобби*, Букмекеры* (*если включены) | вход, роль operator+ |
| `/e/<slug>/settings` | Название, бренд, модули, источник данных, операторы, экспорт события | вход, роль admin |
| `/admin` | Все события, шаблоны, люди, журнал изменений | вход, admin |
| `/card/<slug>?team=&nick=` | Карточка игрока (её грузит OBS) | **публично** |
| `/overlay/<slug>/…` | Оверлей вето для OBS | **публично** (код показа в ссылке) |
| `/assets/…`, `/events/<slug>/brand/…` | Картинки, шрифты, бренд | **публично** |
| сайт вето (отдельный адрес) `/<slug>_<команда>#k=…` | Страница капитана | **публично**, ключ в `#` |

«Публично» — потому что OBS и игроки не умеют входить в систему. Эти страницы не показывают
ничего секретного: карточки, графика, зашифрованное вето.

Адреса в старом виде (`/`, `/veto.html`, `/card.html`) продолжают работать и ведут на событие
`cyberclash`, чтобы не ломать выпущенные ссылки и OBS-коллекции.

## 4. Пакет события

Папка `events/<slug>/` в репозитории или один файл (экспорт из панели):

```
events/
  cyberclash/
    event.json            ← манифест (ниже)
    brand/                ← logo.svg, backdrop.jpg, шрифты
    teams/                ← логотипы команд, teams.json
    players/              ← фото игроков, players.json
  _templates/
    sheets-tournament/    ← шаблон «турнир с таблицами»
    lan/                  ← шаблон «ЛАН»: вписал команды руками
    blank/
```

Манифест `event.json` (v1). Пример для КиберКлэша показывает, куда уезжает то, что сейчас зашито:

```jsonc
{
  "v": 1,
  "slug": "cyberclash",
  "name": "CyberClash",
  "short": "CC",
  "kind": "sheets",                       // sheets | manual (ЛАН) | faceit
  "language": "ru",

  "brand": {
    "logo": "assets/card/cyberclash-logo.png",   // пути — файлы как они лежат сегодня; позже переедут в events/cyberclash/brand/
    "backdrop": "assets/veto-backdrop.jpg",
    "font": { "display": "assets/fonts/Oswald-Variable.ttf", "text": "system" },
    "colors": {
      "accent": "#00d3ef", "deep": "#043746", "black": "#031b24",
      "ban": "#ed1637", "pick": "#2fbf71", "decider": "#f2c14e"
    }
  },

  "modules": { "cameras": true, "veto": true, "obs": true, "server": false, "lobby": true, "bookmakers": true },

  "source": {                              // сейчас DEFAULT_SOURCE в core.js
    "type": "sheets",
    "roster":   { "id": "…", "gid": "…" },
    "schedule": { "id": "…", "gid": "…", "playoffsGid": "…" }
  },

  "veto":    { "pool": ["Ancient","Anubis","Cache","Dust2","Inferno","Mirage","Nuke"],
               "format": "BO3", "timerMinutes": 5, "tournament": "CyberClash" },
  "cameras": { "frame": "inner43" },        // 1320×1008 по центру холста
  "lobby":   { "faceit": true },
  "bookmakers": { "match": ["CyberClash"] },

  "operators": ["admin@example.com"]
}
```

Правила манифеста:
- только данные, **никаких секретов**: ключ FACEIT, пароль RCON, токены остаются в окружении
  сервера (`FACEIT_API_KEY`, `CS2_RCON_PASSWORD`, …) и привязываются к событию по slug;
- есть версия (`v`), старые манифесты читаются новыми версиями кода (миграции в одном месте);
- валидируется при загрузке (`events/schema.js`, `validateEvent`/`loadEvent`): плохой цвет, лишнее поле, неверный slug —
  понятная ошибка, а не поломанный эфир; фото и логотипы проходят тот же контроль, что в режиме ЛАН
  (только небольшие png/webp/jpeg).

## 5. Бренд и дизайн-поверхности

Одна цепочка: **бренд-кит → токены → поверхности**.

| Поверхность | Где живёт | Что берёт из бренда | ТЗ дизайнеру |
|---|---|---|---|
| Бренд-кит | `events/<slug>/brand/` | — (источник) | `docs/design/01-brand-kit.md` |
| Оверлей вето (OBS) | `assets/veto-overlay/` | цвета, лого, шрифт, фон | `docs/design/02-veto-overlay.md` |
| Страница вето капитанов | `veto.html`, `veto.css` | то же | `docs/design/03-captains-veto-page.md` |
| Карточка игрока (OBS) | `card.*`, `lan-event.js` | то же | `docs/design/04-player-card.md` |
| Рамка и сцена «Матрица» | OBS-шаблон | фон и рамка | `docs/design/05-camera-frame-and-matrix.md` |
| Панель оператора | `index.html`, `style.css` | **ничего**: это инструмент, он всегда в стиле Oneshot; бренд события — только полоска/название | — |

**Три уровня кастомизации** (в ТЗ у каждого свой объём работ и срок):
- **L0, токены.** Заказчик дал логотип и цвета → всё красится само. Часы, не дни. Делаем сами.
- **L1, скин поверхности.** Свой фон, форма штампов бан/пик, стиль анимации, но тот же макет.
  Дизайнер отдаёт ассеты и значения токенов.
- **L2, свой макет.** Оверлей или карточка перерисованы целиком. Дизайнер отдаёт и макет,
  и код отрисовки (как мы делаем сейчас с GPT).

Токены — единый словарь, который читают все поверхности:
`accent, deep, black, ink, muted, ban, pick, decider, ct, t` + `logo, backdrop, font.display`.
Для CSS это переменные `--ev-*`, для canvas (оверлей) — объект, собираемый из того же манифеста.

## 6. Модули

Каждый модуль объявляет: `id`, название вкладки, какие данные ему нужны и включён ли по умолчанию.
Оболочка читает `event.modules` и показывает только нужные вкладки; остальное не загружается.

| id | Вкладка | Нужно от события | По умолчанию |
|---|---|---|---|
| `cameras` | Подготовка | источник составов (`sheets` или `manual`) | вкл |
| `veto` | Вето | пул карт, бренд | вкл |
| `obs` | OBS | — | вкл |
| `server` | Сервер | локальный сервер CS2 на этом компьютере | выкл |
| `lobby` | Лобби | FACEIT-турнир | выкл |
| `bookmakers` | Букмекеры | строка для поиска матчей в линиях | выкл |

Сегодняшняя заплатка «скрыть Лобби и Букмекеры, если включён ЛАН» (`lan.js applyEvent`) превращается
в общее правило «показать вкладки включённых модулей».

## 7. Хранилище событий и роли

Интерфейс `EventStore { list(), get(slug), save(event), putAsset(slug, name, bytes), delete(slug) }`.
Модули и панель говорят только с ним. Реализации:

| | Где лежат события | Кто может создавать | Когда |
|---|---|---|---|
| **RepoStore** | `events/` в репозитории | через PR (администратор, я) | **сейчас**: КиберКлэш и постоянные события |
| **BrowserStore** | браузер оператора (как ЛАН) + «Экспорт/Импорт события» одним файлом | любой оператор, для себя | **сейчас**: разовые события, ЛАН |
| **CloudStore** | Cloudflare KV (манифесты) + R2 (картинки) | любой администратор из панели | **когда события начнут запускать другие люди** |

CloudStore и вход людей:
- Вход — **Cloudflare Access** (бесплатно до 50 человек): список e-mail, без своих паролей.
  Панель получает проверенный e-mail в заголовке запроса; роль = запись в манифесте события
  (`operators`) или в общем списке администраторов.
- Публичные пути из раздела 3 в политику Access не входят (OBS и игроки без входа).
- Каждое сохранение события пишет запись в журнал изменений (кто, когда, что) и хранит прошлую версию:
  откат одним нажатием.
- Секреты (ключи FACEIT, RCON) в облачное хранилище **не попадают**: у каждого оператора свои в окружении.

Выбор «сейчас или потом» — вопрос объёма: интерфейс закладываем сразу, CloudStore пишем, когда
появится второй человек, который запускает события сам.

## 8. Состояние в браузере: по событиям

Сейчас ключи localStorage общие на весь сайт (`oneshot-webcam-match-v1`, `oneshot-camera-settings-v1`,
`webcam-desk-source`, …). Когда событий несколько, они перемешаются: настройки камер ЛАНа
уйдут в КиберКлэш. Поэтому ключи получают пространство имён `oneshot:<slug>:<имя>`.

| Что | Область | Ключи сейчас |
|---|---|---|
| Выбранный матч, составы, вето панели | событие | `oneshot-webcam-match-v1`, `webcam-desk-source` |
| Новые/ручные ID потоков, «Кадр» камер, пресет рамки | событие | `oneshot-stream-ids`, `oneshot-camera-settings-v1`, `oneshot-camera-frame-v1`, `oneshot-watch-cams` |
| Режим ЛАН, команды, фото | событие | `oneshot-lan-v1`, `oneshot-lan-assets-v1` (станут частью пакета события) |
| Вето капитанов, лобби, букмекеры | событие | `oneshot-captain-veto`, `oneshot-veto-watch`, `oneshot-lobby`, `oneshot-lobby-log`, `oneshot-bookies` |
| Подключение к OBS, код дока | **оператор** (у каждого свой компьютер) | `oneshot-obs`, `oneshot-obs-bridge` |
| Тема, вкладка, уведомления | **оператор** | `oneshot-theme`, `oneshot-view`, `oneshot-notification-*` |

Миграция: при первом запуске старые ключи копируются в область `cyberclash`, ничего не теряется.

## 9. Структура кода и порядок внедрения

Целевая раскладка (папки появляются по мере фаз; **механический перенос файлов — последним**, он
ничего не меняет по сути, но затрагивает сборку, тесты и артефакт Claude):

```
index.html, style.css         оболочка (выбор события, вкладки по модулям)
modules/<id>/…                cameras, obs, veto, lobby, bookmakers, server, lan
events/<slug>/…               пакеты событий (раздел 4)
events/schema.js              схема и проверка манифеста
core/                         общее: события, хранилище, бренд, ссылки, OBS
brand/                        сборка токенов → CSS/canvas
server/                       локальный сервер, функции Cloudflare
docs/                         эта папка и ТЗ дизайнерам
```

Фазы (каждая — отдельный коммит с тестами, поведение КиберКлэша не меняется):

1. **Манифест и загрузчик.** ✅ *1a сделано*: `events/schema.js`, `events/cyberclash/event.json`, шаблоны, тесты-контракты.
   *1b*: константы (`DEFAULT_SOURCE`, название, цвета, список модулей) читаются из манифеста. Для КиберКлэша результат тот же.
   (Осторожно: генератор сайта вето проверяет, что ID таблицы не попал в его копию `core.js`, — его правим вместе с 1b.)
2. **Пространство имён состояния.** Ключи по slug, миграция старых. Функция `eventKey(slug, name)`.
3. **Модули по манифесту.** Вкладки показываются по `modules`; ЛАН становится событием `kind: manual`.
4. **Бренд из события.** Токены `--ev-*`; карточка, оверлей, страница вето читают бренд (L0 у всех).
5. **Выбор события и адреса `/e/<slug>/`.** Страница `/`, переключатель в шапке, старые адреса ведут на `cyberclash`.
6. **BrowserStore: «Новое событие» из шаблона, экспорт/импорт.**
7. **CloudStore + Access + роли + журнал** — когда появятся другие операторы.
8. **Перенос файлов в `modules/` и `core/`.**

ЛАН-версия, которая готова сейчас, переживёт все фазы: ЛАН — это событие с `kind: manual`.

## 10. Что намеренно не делаем

- Форк репозитория на турнир: через полгода одна и та же правка в пяти местах.
- Плагины, менеджер пакетов, отдельные репозитории модулей: для одной команды это лишний вес.
- Тему панели под бренд заказчика: панель — рабочий инструмент оператора, а не витрина.
- Хранить секреты в событии.

## 11. Риски и как их закрыть

| Риск | Что делаем |
|---|---|
| Рефакторинг ломает эфир | фазы маленькие, по тестам; прод получает фазу только после репетиции |
| Старые OBS-коллекции и ссылки перестанут работать | старые адреса остаются на `cyberclash`; формат OBS JSON не меняется |
| События перемешают состояние | пространство имён по slug + тест «два события в одном браузере» |
| Чужой оператор испортил событие | роли, журнал, откат версии |
| Бренд заказчика ломает читаемость | проверка контраста при загрузке бренда, предупреждение в настройках события |
| Картинки раздувают браузерное хранилище | те же лимиты размера, что у фото в режиме ЛАН; большое — в R2 |

# ТЗ: редизайн графики вето под бренд события

Для того, кто делает дизайн (человек или ИИ с доступом к репозиторию
`ssolutionn/Oneshot-Panel`). Задача — новое оформление **без изменения логики**:
меняется, как вето выглядит и анимируется, а не как оно работает.

## 1. Что делаем (поверхности)

1. **Оверлей вето для OBS** — `assets/veto-overlay/` (`overlay.html`, `overlay.css`, `scene.js`,
   `smoke.js`). Рисуется на `<canvas>` 1920×1080. Два вида:
   - `layout=full` — полный кадр 1920×1080, прозрачные места под камеры не нужны (фон свой);
   - `layout=strip&crop=1` — плашка **1920×400**, фон **прозрачный** (ставится поверх камер на X=0, Y=680).
2. **Страница вето капитанов** — `veto.html`, `veto.css` (+ `assets/veto-appearance.js` для дыма/прогресса).
   Тёмная, адаптивная (телефон 375 px … десктоп), английский по умолчанию и русский.
3. **Эфирная карточка игрока** — для ЛАНа её собирает `eventCardHtml()` в `lan-event.js`
   (1920×1080, фото игрока, лого команды, ник). Токены цветов — вверху функции (`DEFAULT_COLORS`,
   CSS-переменные `--accent --deep --black --cyan --teal`). Для CyberClash — `card.html` и `card.css`.

## 2. Контракт данных оверлея (его менять нельзя)

Оверлей получает снимок и считает модель в `model.js` (`snapshot`, `viewModel`):

```
{ version:1, teams:[A,B], format:'BO1'|'BO2'|'BO3'|'BO5', first:0|1,
  actions:[{map, type:'ban'|'pick', team:0|1, side?:'CT'|'T'}], pending:null|'MapName', stage:'GROUP STAGE' }
```

Из `viewModel` рисуется всё: `slots[]` — **колонки по ходам** (в BO3: BAN BAN PICK PICK BAN BAN DECIDER; 7 колонок),
у каждого `{id:'turn-N', role, name, status:'available'|'ban'|'pick'|'pending'|'leftover', team, sideTeam, side, ownSide, step}`,
плюс `teams`, `stage`, `format`, `nextTeam`, `nextType`, `leftoverLabel` ('DECIDER' или 'MAP 02' для BO2).
Сторона (CT/T) у пика принадлежит **сопернику** команды, выбравшей карту.

Карты — 7 штук: Ancient, Anubis, Cache, Dust2, Inferno, Mirage, Nuke (`assets/maps/*.jpg`, MIT, можно кадрировать).

API страницы, которое должно остаться: `window.vetoOverlay.{setState(snapshot,{animate}), getState, png, setLayout, stopMotion, description}`.
`?preview=1` (демо с кнопками) и `&step=0..6`, `&format=`, `&motion=off`, `&animations=off` — продолжают работать.

## 3. Поведение и анимации (сохранить смысл, стиль — свободный)

| Событие | Что видно | Время |
|---|---|---|
| Бан | карта обесцвечивается, красный крест/штамп | 900 мс |
| Пик | подсветка, рамка, штамп PICK; он появляется **сразу**, ещё до выбора стороны соперником | 900 мс |
| Выбор стороны | CT/T показывается на карточке пика; не проигрывает пик заново | — |
| Решающая карта | появляется **через 1500 мс** после последнего хода | 1500 мс задержка |
| Отмена хода (undo) | карточка возвращается в «пустую» | 650 мс |
| Повторный снимок (каждые 2,5 с) | **ничего не перезапускает** | — |
| Перезагрузка источника / поздний старт | сразу итоговое состояние без анимации | — |

Дополнительно: уважать `prefers-reduced-motion` (без дыма и переходов), давать запасной вариант без WebGL
(Canvas2D). Название стадии, команды (длинные имена до 100 символов, кириллица), счётчик хода («кто сейчас ходит»).

## 4. Жёсткие ограничения (чтобы ничего не сломалось в эфире)

- **Без сети.** Никаких CDN, Google Fonts, внешних картинок, видео по ссылкам. Шрифты и картинки — файлы в `assets/`.
  CSP сайта `script-src 'self'; style-src 'self'; img-src 'self'` — **не менять**; никаких inline-скриптов/стилей,
  `data:`-картинок в самих страницах (в карточке для OBS data: допустим — она отдельный документ).
- Работает в **браузерном источнике OBS (CEF)** и в Chrome/Safari: проверять в обоих. WebGL там может быть выключен.
- Фон плашки `strip` — **прозрачный** (alpha); PNG-экспорт тоже с прозрачностью.
- Читаемость на стриме: основные тексты ≥ 28 px при 1080p, контраст ≥ 4.5:1, не полагаться на один цвет
  (бан/пик отличаются ещё и формой/надписью).
- Производительность: 60 fps не требуется, но без лагов на слабом ноуте обсервера; частицы/дым ограничить.
- Размер: один источник ≤ ~3 МБ ассетов; шрифты только нужные начертания.
- Не трогать: `model.js` (логика), протокол доставки в `overlay.js` (VDO/relay, `veto-state`/`veto-received`),
  `core.js` (правила вето и порядок), подписи и ключи капитанов (`veto-room.js`), `veto.js` логика.

## 5. Как оформить токены (сделать первым шагом)

Вынести в одно место: цвета (ink, muted, faint, accent, deep, panel, ban, pick, decider, gold),
имя шрифта, путь к логотипу события, толщины рамок, радиусы, длительности анимаций.
В `scene.js` это объект `C` (+ `W,H`), в `veto.css` — переменные `--vt-*`, в карточке — `--card-*`.
После этого брендинг = замена значений + замена файлов логотипа/фона.

## 6. Что сдать

1. Изменённые файлы (оверлей, страница вето, карточка при необходимости) — одним коммитом.
2. Скриншоты/PNG: полный кадр и плашка на шагах 0, 2, 4, 6 для BO1, BO3, BO5 (демо: `overlay.html?preview=1`).
3. Короткая записка: какие токены поменяны и где лежит логотип.

## 7. Приёмка (должно пройти без правок)

```sh
npm run check && npm test
python3 scripts/qa_veto_overlay.py      # пиксели, анимации, PNG 1920×1080/1920×400 с альфой, reduced-motion
python3 scripts/qa_veto_site.py --url http://127.0.0.1:3000 --chromium /path/to/chrome   # страница капитанов, 375 px
python3 scripts/qa_live.py --url http://127.0.0.1:3000 --chromium /path/to/chrome        # оверлей в панели
```

Дополнительно вручную: длинное название команды («Very Long Team Name Esports Club»), ник из 20 символов,
BO1/BO2/BO3/BO5, ночь/день панели не затрагиваются (оверлей и страница вето — всегда тёмные).

# Проверка правки

## Когда

Перед каждым коммитом, пушем и после правки, которая может задеть поведение
(JS, HTML, CSS, сервер, функции, сценарии). Для правки только документации
достаточно `npm run check`.

## Шаги

1. `git status --short` и `git diff --stat` — зафиксировать изменённые файлы.
   Не смешивать правки кода и тестов в одном шаге.
2. `npm run verify -- --dry-run` — посмотреть, что выбрано, и что осталось без
   проверки (`нет проверок для: …`). Если список неверный — поправить
   `scripts/agent/suites.json`, а не обходить пульт.
3. `npm run verify` — дождаться вердикта. Быстрая проверка без браузеров:
   `npm run verify -- --tier T0`.
4. Прочитать `artifacts/agent/<runId>/report.json` (и `index.md`, если нужен
   обзор). Вердикт — только `verdict`, не последняя строка консоли.
5. Красное — перейти в скилл `triage-failure`. Зелёное — проверить
   `summary.skip` и `selection.unmatched`: что именно осталось непроверенным.

## Чтение отчёта

- `verdict`: `pass` — зелено, `fail` — есть провалы, `env` — не проверено.
- `suites[].status`: `pass`, `fail`, `skip`, `error`.
- `suites[].scenarios[]`: шаги; у браузерных — из `PASS:`, у node — из TAP.
- `suites[].evidence[]`: скриншоты и файлы, приложить пути, не пересказывать.
- `summary.skip` с причиной — перечислить человеку.

## Стоп

- `env` (код 2) — не чинить код: сообщить, чего не хватает
  (`playwright`, браузер, Pillow, OBS, сеть).
- В выводе засветился секрет (FACEIT, пароль OBS или комнаты, `#k=`/`#v=`) —
  остановиться, вычистить артефакты и сообщение.
- Проверка требует сети или настоящего OBS — это T2, в PR не запускать.

## Не делать

- не править `test/**` и `scripts/qa_*` в том же шаге, что и код;
- не добавлять `skip`/`retry`, чтобы получить зелёное;
- не запускать `--tier T2` и `--all` в обычном PR-цикле;
- не пересказывать скриншоты словами вместо ссылок на файлы.

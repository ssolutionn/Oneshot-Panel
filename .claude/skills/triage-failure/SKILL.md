# Разбор падения

## Когда

`npm run verify` вернул `fail` или `env`. Сначала класс, потом правка.

## Шаги

1. Открыть `artifacts/agent/<runId>/report.json`, найти упавшие suites.
2. Для каждой: `status`, `reason`, `errorClass`, `scenarios[]` со `status: fail`,
   `evidence[]` и лог рядом (`<suite>/suite.log`, `<suite>/*.log`).
3. Определить класс по таблице ниже.
4. Сформулировать минимальный эксперимент: один сценарий, один браузер, без
   остальных проверок.
5. Повторить ровно один раз:
   `npm run verify -- --only <suite>` (для браузерных — с `--url`, если сервер
   уже поднят). Второй повтор — это уже карантин, а не диагностика.

## Классы

| Признак | Класс | Действие |
|---|---|---|
| падает сценарий, затронутый диффом, повторяется 2/2 | регрессия | чинить код |
| падает сценарий вне диффа стабильно | дрейф контракта | сверить AGENTS.md «Что нельзя ломать», потом код |
| `errorClass: env`, `env`-вердикт | окружение | не чинить код, сообщить чего нет |
| падает 1/2, проходит при повторе | флак | запись в `docs/agent-testing/flakes.json` (owner, issue, expires) |
| падает утверждение внутри мока (VDO, Sheets, OBS) | поломка прибора | чинить `scripts/qa_*` отдельным PR |
| нет `evidence` и нет внятного `error` | нет доказательства | `error`, повторить с `--verbose` |

## Правила

- Причина важнее кода возврата: `fail` без trace/скриншота — это `error`.
- Один и тот же сценарий с разными данными — всё ещё один баг.
- Правка теста допустима только как отдельное решение: объяснить, почему
  старое утверждение было неверным, и не ослаблять его.
- Просроченный карантин — красный гейт, а не повод продлить.

## Стоп

- Два одинаковых падения по окружению — остановиться, отчёт человеку.
- Больше 20 минут на T1 без прогресса — остановиться и сузить выборку.
- Падение указывает на секрет в логе — сначала вычистить артефакты.

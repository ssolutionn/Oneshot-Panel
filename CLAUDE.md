# Правила для Claude

Карта файлов, протоколы и «что нельзя ломать» — в `AGENTS.md` (выше). Здесь только
то, что касается проверки кода и безопасности. Правила ревью конкретно этого
проекта — в `REVIEW.md`, политика уязвимостей — в `SECURITY.md`.

## Перед пушем

1. `npm run check` — синтаксис всех `.js/.mjs` (скрипт сам находит файлы).
2. `npm test` — все тесты. Красные тесты не обходить: не пропускать, не отключать.
3. Менял `server/`, `functions/`, `assets/veto-*`, `scripts/build-veto-site.mjs`,
   `_headers`, `netlify.toml` или `server.js`? Тогда ещё `/security-review`.
4. Менял вето-часть? Репозиторий `oneshot-veto` — **сгенерированная копия**:
   `node scripts/build-veto-site.mjs <dir>`, затем
   `npm run check:veto-sync -- <путь к oneshot-veto>` должен пройти.
   Руками в `oneshot-veto` ничего не править — только пересборка отсюда.
5. Перед PR: `/code-review`, критичное (см. REVIEW.md) помечай в описании PR.

## Безопасность: инварианты

- Секреты (`FACEIT_API_KEY`, `CLOUDFLARE_API_TOKEN`, пароли OBS/VDO, коды связи,
  ключи капитанов) не попадают в код, логи, URL, `localStorage` и тексты ошибок.
  Ключ капитана живёт только во фрагменте `#…` ссылки.
- Реле (`server/`, `functions/api/veto-*`) принимает только подписанные ECDSA-пакеты
  жёсткой формы (`packetShape`), с лимитом размера/частоты. Не ослаблять проверки
  формы, окна времени (±120 с) и подписи ради «удобства».
- В `innerHTML` данные из таблицы, FACEIT, VDO или `localStorage` — только через
  `escapeHtml`. Ссылки из внешних данных — только `https:` и ожидаемый хост.
- `postMessage` принимать лишь после проверки `event.source` (и `event.origin`, где
  источник известен). Отправлять с явным origin, `'*'` — только для запечатанных
  (AES-GCM) данных.
- Прокси FACEIT: ключ сайта только для запросов с доказанным своим origin
  (`fromThisSite`); пропускаются лишь пути лобби из `ALLOWED`.
- CSP/заголовки живут в четырёх местах (`_headers`, `netlify.toml`, `server.js`,
  генератор вето в `scripts/build-veto-site.mjs`); `test/server.test.js` держит
  первые три в синхроне. Менять все сразу. Inline-скриптов и стилей нет — не
  добавлять `'unsafe-inline'`.
- GitHub Actions: `permissions` минимальные, `persist-credentials: false` там, где
  не пушим; секреты передаются только шагам, которым они нужны, не на весь job.
  Данные из PR/issue (`github.event.*`) в `run:` подставлять только через `env:`.
- Внешних npm-зависимостей нет и не добавлять (см. AGENTS.md). Vendor-файлы в
  `assets/vendor/` не править.

## Стиль

Код читается как соседний: тот же отступ, краткие комментарии «почему», русские
тексты интерфейса. Не рефакторить попутно — правка минимальная под задачу.

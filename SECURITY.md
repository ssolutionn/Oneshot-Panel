# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Напишите владельцу репозитория (`ssolutionn`) в личные
сообщения GitHub или используйте **Security → Report a vulnerability** в репозитории.
Укажите: что именно, как воспроизвести, что можно получить. Ответ — в течение нескольких
дней. Секреты в сообщение не вкладывайте.

## Модель угроз (кратко)

| Актив | Угроза | Защита |
|---|---|---|
| Ссылки капитанов | подмена хода/комнаты | ключ только во фрагменте `#`, AES-GCM, пакеты реле подписаны ECDSA P-256 |
| Реле вето (Worker/Node) | подделка, повтор, перегруз | строгая форма пакета, окно ±120 с, лимит 24 записи/10 с на тему, лимит размера, хранение 7 дней |
| Ключ FACEIT сайта | трата ключа чужими | только для запросов со своего origin, только пути лобби |
| Токен Cloudflare | кража через CI | токен только в шагах деплоя, `permissions: contents: read` |
| Панель в браузере | XSS, внешние скрипты | CSP без `unsafe-inline`, экранирование, `frame-ancestors 'none'` |
| Пароль OBS | утечка | не хранится панелью, не попадает в URL и логи |

## Известные ограничения (нужна настройка вне кода)

- Реле и короткие ссылки **без аутентификации**: любой может создать тему/запись
  (данные зашифрованы, но место занимают; короткие записи не истекают). Включите в
  Cloudflare **Rate limiting rule** на `/api/veto-relay` и `/api/veto-link`
  (напр. POST ≤ 30 за 10 с с одного IP) и следите за расходом Durable Objects.
- Ротация: `CLOUDFLARE_API_TOKEN` с правами только Workers/Pages на нужный аккаунт,
  `FACEIT_API_KEY` — сменить при малейшем подозрении.
- В GitHub включите: Secret scanning + Push protection, Dependabot alerts, Code scanning
  (CodeQL уже в workflow), защиту веток с обязательным ревью владельцев кода.
